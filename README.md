# Зелёный Сад

**Живой сайт:** [progardengreen.ru](https://progardengreen.ru)

Учебный интернет-магазин саженцев на Django 5.2.

Проект реализует каталог растений, корзину, оформление заказов, регистрацию пользователей, вход с OTP-кодом, личный кабинет, избранное, отзывы и купоны.

---

## 1. Назначение проекта

`Зелёный Сад` — веб-приложение интернет-магазина саженцев деревьев и кустарников.

Основные цели проекта:

- изучение Django 5.2 на примере полноценного интернет-магазина;
- практика работы с моделями, формами, шаблонами и ORM;
- реализация базовой аутентификации и OTP-подтверждения;
- работа с корзиной на основе пользовательской сессии;
- применение принципов безопасной разработки веб-приложений.

## 4. Основные сущности

### Category

Категория товара.

Основные поля:

- `name` — название категории;
- `slug` — человекочитаемый URL-идентификатор.

### Product

Товар в каталоге.

Основные поля:

- `category` — категория товара;
- `name` — название;
- `slug` — URL-идентификатор;
- `image` — изображение;
- `description` — описание;
- `price` — цена;
- `available` — доступность товара;
- `created` — дата создания.

### Order

Заказ пользователя.

Основные поля:

- `user` — пользователь;
- `first_name` — имя покупателя;
- `phone` — телефон;
- `address` — пункт самовывоза;
- `comment` — комментарий к заказу;
- `payment_method` — способ оплаты;
- `coupon` — применённый купон;
- `discount` — размер скидки;
- `paid` — статус оплаты;
- `created` — дата создания.

### OrderItem

Позиция заказа.

Основные поля:

- `order` — заказ;
- `product` — товар;
- `price` — цена товара на момент покупки;
- `quantity` — количество.

### Review

Отзыв пользователя о товаре.

Основные поля:

- `product` — товар;
- `user` — автор;
- `text` — текст отзыва;
- `rating` — оценка от 1 до 5;
- `created` — дата создания.

### Favorite

Избранный товар пользователя.

Основные поля:

- `user` — пользователь;
- `product` — товар;
- `created` — дата добавления.

### Coupon

Промокод.

Основные поля:

- `code` — код купона;
- `discount` — процент скидки;
- `active` — активность;
- `valid_from` — дата начала действия;
- `valid_to` — дата окончания действия.

### OTPCode

Одноразовый код подтверждения.

Основные поля:

- `user` — пользователь;
- `code_hash` — хеш OTP-кода;
- `created` — дата создания;
- `is_used` — признак использования.

## 6. Переменные окружения

Для запуска проекта используется файл `.env`.

Пример:

```env
SECRET_KEY=your-secret-key
DEBUG=False
DATABASE_URL=postgres://user:password@host:port/dbname
CLOUDINARY_URL=cloudinary://api_key:api_secret@cloud_name
RESEND_API_KEY=your-resend-api-key
```

### Описание переменных

| Переменная       | Назначение                      | Обязательность  |
|------------------|---------------------------------|-----------------|
| `SECRET_KEY`     | Секретный ключ Django           | обязательно     |
| `DEBUG`          | Режим отладки                   | обязательно     |
| `DATABASE_URL`   | URL production-базы данных      | опционально     |
| `CLOUDINARY_URL` | URL Cloudinary-хранилища        | опционально     |
| `RESEND_API_KEY` | API-ключ сервиса Resend         | нужно для email |

> **Важно:** реальные значения секретов нельзя хранить в репозитории.

## 7. Установка и запуск

### 7.1. Клонирование проекта

```bash
git clone https://github.com/Logo-website/django-shop.git
cd django_shop
```

### 7.2. Создание виртуального окружения

Windows:

```bash
python -m venv venv
venv\Scripts\activate
```

Linux / macOS:

```bash
python3 -m venv venv
source venv/bin/activate
```

### 7.3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 7.4. Настройка `.env`

Создайте файл `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Заполните необходимые значения.

### 7.5. Применение миграций

```bash
python manage.py migrate
```

### 7.6. Создание администратора

```bash
python manage.py createsuperuser
```

### 7.7. Запуск сервера разработки

```bash
python manage.py runserver
```

После запуска приложение будет доступно по адресу:

```
http://127.0.0.1:8000/
```

Админ-панель:

```
http://127.0.0.1:8000/admin/
```

## 9. Безопасность

В проекте используются следующие меры защиты:

- хранение паролей через стандартные механизмы Django;
- валидация сложности пароля;
- CSRF-защита для POST-форм;
- экранирование пользовательских данных в шаблонах;
- безопасные cookies в production-режиме;
- HTTPS redirect в production-режиме;
- HSTS-заголовки;
- защита от clickjacking через `X_FRAME_OPTIONS = 'DENY'`;
- хранение OTP-кодов в виде хеша;
- проверка срока действия OTP-кодов;
- использование `secrets` для генерации OTP;
- проверка `SECRET_KEY` при запуске;
- защита от небезопасных внешних редиректов;
- хранение цены заказа на момент покупки.

### Рекомендации для production

Перед production-запуском рекомендуется дополнительно:

- включить rate limiting для OTP, входа и восстановления пароля;
- использовать полноценный email backend;
- исключить вывод персональных данных через `print`;
- добавить мониторинг ошибок;
- добавить логирование security-событий;
- настроить резервное копирование базы данных;
- регулярно обновлять зависимости;
- использовать PostgreSQL вместо SQLite.

## 10. Работа с корзиной

Корзина хранится в пользовательской сессии.

В сессии сохраняются:

- ID товара;
- количество товара.

Цена товара не хранится в сессии. При расчётах она берётся из базы данных, что защищает заказ от подмены стоимости на стороне клиента.

---

## 11. Работа с купонами

Купон применяется к корзине и сохраняется в сессии.

При оформлении заказа купон повторно проверяется:

- существует ли он;
- активен ли;
- не истёк ли срок действия;
- не был ли уже использован пользователем.

После оформления заказа купон сохраняется в заказе вместе с размером скидки.

---

## 12. Аутентификация и OTP

Проект использует регистрацию и вход по email.

**При регистрации:**

1. Пользователь вводит email и пароль.
2. Аккаунт создаётся неактивным.
3. На email отправляется OTP-код.
4. После подтверждения OTP аккаунт активируется.

**При входе:**

1. Пользователь вводит email и пароль.
2. Если пароль верный, генерируется OTP-код.
3. OTP отправляется на email.
4. После успешного ввода OTP пользователь входит в систему.

OTP-коды хранятся в базе данных в виде хеша.
